# فایل‌های دیتابیس — کدام را کِی اجرا کنم؟

خیلی مهم: **ترتیب و انتخاب درست فایل**، وگرنه نصب خراب می‌شود.

---

## اگر Supabase دارید (ابری یا Docker روی سرور خودتان)

```
1️⃣  01_full_schema.sql        ← ساختار کامل (۴۷ جدول)
2️⃣  02_first_admin.sql        ← ساخت کاربر مدیر سیستم
```

⛔ فایل `00_compat_plain_postgres.sql` را **اجرا نکنید**.
⛔ فایل `01b_full_schema_plain_postgres.sql` را **اجرا نکنید**.

این دو فایل ساختار داخلی Supabase را خراب می‌کنند.

**روش اجرا:** پنل Supabase → SQL Editor → New query → محتوای فایل را
کپی کنید → Run

---

## اگر PostgreSQL معمولی ویندوز دارید (بدون Supabase)

```
1️⃣  00_compat_plain_postgres.sql          ← لایه سازگاری
2️⃣  01b_full_schema_plain_postgres.sql    ← ساختار کامل
```

⛔ فایل `02_first_admin.sql` اینجا کار نمی‌کند (نیاز به Supabase Auth دارد).

**روش اجرا:** فایل `scripts\1-install-database.bat` را اجرا کنید —
هر دو مرحله را خودکار انجام می‌دهد.

یا دستی در Command Prompt:
```cmd
psql -U postgres -d erp_sanatsabz -f 00_compat_plain_postgres.sql
psql -U postgres -d erp_sanatsabz -f 01b_full_schema_plain_postgres.sql
```

### این حالت به چه دردی می‌خورد؟

| کار | کار می‌کند؟ |
|---|---|
| اتصال Power BI و گزارش‌گیری | ✅ بله |
| نگهداری داده‌ها در SQL | ✅ بله |
| اجرای خود سامانه ERP | ❌ نه — Supabase لازم است |
| ورود کاربران با نام کاربری/رمز | ❌ نه |

چون سامانه برای ورود کاربران و کنترل دسترسی به Supabase نیاز دارد،
PostgreSQL تنها برای نگهداری ساختار و گزارش‌گیری مناسب است.

---

## چه چیزی ساخته می‌شود؟

| مورد | تعداد |
|---|---|
| جدول | ۴۷ |
| قانون امنیتی (RLS Policy) | ۱۶۰ |
| کلید و محدودیت | ۱۰۳ |
| تابع امن | ۳۳ |
| تریگر | ۸ |
| ایندکس | ۷۰ |

**داده‌ی کسب‌وکاری: هیچ.** دیتابیس کاملاً خالی تحویل می‌شود تا
کاربران واقعی از صفر اطلاعات را وارد کنند.

تنها داده‌های پایه که ساخته می‌شوند:
- ۸ سمت سازمانی (مدیرعامل، مدیرتولید، برنامه‌ریزی تولید، …)
- ۷ مرحله‌ی گردش کار پیش‌فرض
- ۲ تنظیم اولیه (زبان، تم)

---

## تست‌شده

این فایل‌ها قبل از تحویل، روی یک PostgreSQL ۱۶ کاملاً خالی نصب و
بررسی شده‌اند: بدون هیچ خطا، و تعداد جدول‌ها/قوانین/کلیدها دقیقاً
برابر با دیتابیس عملیاتی فعلی.

---

## پشتیبان‌گیری

فایل `scripts\3-backup-database.bat` را در **Task Scheduler** ویندوز
زمان‌بندی کنید تا هر شب خودکار پشتیبان بگیرد (و پشتیبان‌های قدیمی‌تر
از ۳۰ روز را پاک کند).

⚠️ حتماً یک بار بازیابی را تست کنید. پشتیبانی که تست نشده، پشتیبان نیست.

```cmd
pg_restore -U postgres -d erp_new --no-owner --no-privileges erp_2026-01-01_02-00.dump
```
